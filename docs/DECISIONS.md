# Decisions log

Decisions taken where the spec is silent or where the environment forced a deviation. Major architectural decisions
have an ADR in `docs/adr/`.

| # | Date | Decision | Why | Revisit when |
|---|---|---|---|---|
| D1 | 2026-11-20 | Pin known-stable major lines (Node 22 LTS, TypeScript 5.9, Next.js 15.5, React 19.1, NestJS 11, Prisma 6.19, Zod 3.25, Vitest 3, ESLint 9) instead of the newest majors on npm (TS 7, Prisma 7/8-rc, Zod 4, ESLint 10). | Spec asks for "latest stable"; several newest majors are very recent or pre-release (Prisma `latest` tag is an RC) with breaking API changes not yet verified for this stack. Exact versions are pinned (`save-exact`). | Scheduled dependency upgrade after Phase 3, one major at a time with the full test suite. |
| D2 | 2026-11-20 | Sessions are stored in PostgreSQL (`Session`, token SHA-256 only), not Redis. Redis is used for rate limiting/caching/queues. | Needs durable listing and revocation ("session list with revoke", "logout everywhere"), auditable and transactional with role changes. One indexed lookup per request. | If session lookups show up in p95 latency, add a Redis read-through cache keyed by token hash. |
| D3 | 2026-11-20 | CSRF: SameSite=Lax httpOnly cookie + mandatory `x-mzn-csrf: 1` header on unsafe methods + Origin check. Webhooks exempt (signature-verified). | Custom header forces a CORS preflight, which strict CORS rejects cross-site; simpler than synchronizer tokens and works with the same-origin proxy. | — |
| D4 | 2026-11-20 | Browser talks only to the portal origin; Next.js rewrites `/api/v1/*` to the API (Caddy routes it directly in Compose). | One origin → cookies without `Domain`, `__Host-` prefix in production, strict CSP `connect-src 'self'`. | — |
| D5 | 2026-11-20 | Every route must declare `@Public()`, `@Authenticated()` or `@RequirePermissions()`; the app refuses to boot otherwise and the global guard fails closed. | Makes "every API route declares the permission it requires" mechanically enforced and lets tests be generated from route metadata. | — |
| D6 | 2026-11-20 | Staff (any role with `isStaff`) and any MFA-enabled user get a session with `mfaSatisfied=false` after the first factor; only `allowPendingMfa` routes work until TOTP is verified/enrolled. Token is rotated on elevation. | Mandatory staff MFA without a separate pre-auth token type; rotation prevents fixation. | OIDC/SAML (IdentityProvider) may satisfy MFA upstream later. |
| D7 | 2026-11-20 | Progressive lockout: lock at every 5th consecutive failure, 15 min doubling, capped at 24 h; plus fixed-window rate limits per IP and per account. | ASVS 2.2.1 guidance; avoids permanent lockout DoS. | Tune with pilot data. |
| D8 | 2026-11-20 | Registration never reveals whether an email exists (same 202; owner receives an "account exists" email). Password reset and email OTP requests behave the same. | Account enumeration resistance. | — |
| D9 | 2026-11-20 | Staff accounts are created by admins without a password; an invitation uses a 30-min password-reset token. | No shared/initial passwords; individual accounts. | Make invite TTL configurable if needed. |
| D10 | 2026-11-20 | Audit log: DB trigger blocks UPDATE/DELETE/TRUNCATE for all roles; BEFORE INSERT trigger computes a SHA-256 hash chain under an advisory lock; runtime role additionally lacks UPDATE/DELETE grants in Compose. Change metadata is sanitized (sensitive keys redacted, long strings truncated). | Tamper-evidence and append-only at the DB layer, not just in code. Serialized inserts are acceptable at expected audit volume. | If audit inserts become a bottleneck, move to per-partition chains. |
| D11 | 2026-11-20 | Field encryption uses AES-256-GCM with a key id in the ciphertext and decrypt-only previous keys (`APP_ENCRYPTION_KEYS_OLD`); associated data binds ciphertext to its owner/purpose. | Supports key rotation without downtime; prevents ciphertext swapping between users. | Move key to a KMS when hosting is chosen. |
| D12 | 2026-11-20 | Arabic is always the default locale: next-intl `localeDetection: false` (Accept-Language ignored); an explicit switch persists via cookie and, when signed in, `User.locale`. | Spec: Arabic default. Browser defaults are often English even for Arabic speakers. | — |
| D13 | 2026-11-20 | Navigation items for not-yet-built modules are hidden (`apps/web/src/lib/implemented.ts`) rather than shown as placeholders. | "No fake internal features." | Each phase adds its keys. |
| D14 | 2026-11-20 | Worker uses a small interval scheduler with transaction-scoped Postgres advisory locks (no Redis needed); BullMQ will be introduced for queued work (email/outbox fan-out) when Redis-backed queues are required. | Phase 0/1 jobs are periodic maintenance; advisory locks give single-runner semantics across replicas and are safe with pooling. | Phase 7 (outbox delivery). |
| D15 | 2026-11-20 | Next.js CSP allows `'unsafe-inline'` scripts (required by App Router hydration without nonces). | Nonce-based CSP requires dynamic rendering of every page; deferred. | Phase 11 security hardening: move to nonce-based CSP. |
| D16 | 2026-11-20 | Local development without Docker: `scripts/dev-db.sh` initialises a project-local PostgreSQL cluster (`.local/pgdata`, 127.0.0.1:55432, SCRAM auth). | Build machine has PostgreSQL binaries but no Docker; avoids touching any other local database. | — |
| D17 | 2026-11-20 | Integration tests never reset the database (Prisma blocks AI-invoked `migrate reset`); they run `migrate deploy` + idempotent seed and create unique data per test. | Safe, non-destructive, also makes tests robust to leftovers. | — |
| D18 | 2026-11-20 | Next.js `output: 'standalone'` is enabled only when `NEXT_OUTPUT_STANDALONE=true` (Docker build). | Standalone tracing creates symlinks, which Windows blocks without Developer Mode. | — |
| D19 | 2026-11-20 | Dates/times render with Latin digits in both locales (Gregorian default, Hijri Umm al-Qura optional), in `Asia/Riyadh`. | Consistency for IDs, amounts and times in mixed-direction text. | Owner preference may change to Arabic-Indic digits. |
| D20 | 2026-11-20 | A shared `packages/db` package owns the Prisma schema, client, field crypto and RBAC sync (spec listed `packages/shared` and `packages/ui` only). | API, worker and seed all need the same client; keeps server-only code (node:crypto) out of the browser-safe `shared` package. | — |
